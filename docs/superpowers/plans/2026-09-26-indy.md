# Indy: the rebuild

The artifacts app becomes Indy. Design reference: the Claude Design canvas
https://claude.ai/artifact/JfXqWdZbm25CrYpLMs6tFi (pages "Workbench · dark", "Brand · Indy",
"Forms, sharing, setup").

## Scope, settled with the operator

- One owner, self-hosted. Local or a VPS with minimal setup: one container, one port, one `/data`
  volume. `INDY_URL` is the only required setting. `RESEND_API_KEY` is optional and unlocks email:
  a sign-in code as a second step for the owner, email-confirmed share links, and response
  notifications.
- Owner signs in with email and password, created on a first-run setup page. `INDY_AUTH=local`
  skips sign-in for a trusted local install.
- Dark Workbench UI: sidebar library (Needs you, Recent, Pinned, Live, Projects, Series, Archive),
  ⌘K search and commands, j/k navigation, rendered side-by-side compare, rendered editing where
  every block is a TipTap node, forms, sharing (private, link, email-confirmed link).
- MCP server `indy`, tools `artifact_*`. Agents outside Orca collect comments with `artifact_wait`.
  Comments and responses from visitors never reach an agent until the owner forwards them.
- Brand: the monoline sand sack, sand accent `#D9B26F`, Geist for the interface, Source Serif 4
  for prose, Bricolage Grotesque for the wordmark only.

## Architecture changes

1. **Styling.** Tailwind v4 and shadcn/ui (Radix) for the app shell and every interactive control,
   themed from CSS variables. `--art-*` theme files stay the contract for artifact content and
   sandboxed frames; the app maps its own tokens onto them so both read as one system.
2. **Document model.** Markdown stays the record. `lib/doc` parses markdown (the existing remark
   pipeline with directives) into a ProseMirror document. Each top-level node carries the source
   it came from. Serialising writes untouched blocks back byte for byte and re-serialises only the
   blocks that changed. Anything the schema cannot model becomes a `rawBlock` node that keeps its
   markdown and renders through the old HTML pipeline, so no document is ever damaged by opening
   it.
3. **One renderer.** The viewer and the editor are the same TipTap instance; editing is a toggle.
   Charts, KPI tiles and tables keep the `art-*` custom elements, wrapped in React node views.
   Node views put `data-block` and `data-lines` on each top-level block, so comment anchors keep
   working unchanged.
4. **Live documents.** The Yjs document holds a `Y.XmlFragment` bound to TipTap instead of a
   `Y.Text` of markdown. The document server seeds from markdown through the shared schema, and
   writes a version when an editor presses Done or an agent finishes typing, not on every pause.
   `artifact_type` inserts nodes and types their text into the fragment.
5. **One port.** `start.mjs` becomes a small proxy: `/collab` upgrades go to the document server,
   everything else to Next. Both on loopback.
6. **Access.** Every request resolves to the owner session, a share-link visitor, a signed URL
   (for requests from opaque-origin frames, which carry no cookies) or an MCP bearer token.

## Phases, each ending green and committed

1. Foundation: rename, config, schema migrations, auth (setup, sign-in, sessions, email code),
   tokens, MCP bearer auth, access checks, one-port proxy, tool renames.
2. Shell and library: tokens, fonts, shadcn, sidebar, Needs you, recent table, filters, projects,
   series, pin, archive, seen state, j/k, ⌘K with SQLite FTS5.
3. Document model and viewer: schema, markdown ↔ ProseMirror with round-trip tests over every
   stored artifact, TipTap viewer with node views, comments ported, versions, live refresh.
4. Rendered editing: toggle, bubble menu, block handle, slash menu, per-block controls, Yjs on the
   fragment, commit on Done, `artifact_type` rewritten.
5. Compare: block alignment, word diff, linked scroll, inline and source modes, restore.
6. Forms: field and choice blocks, submit bar, validation, responses, results view, CSV,
   `artifact_responses`.
7. Sharing: share dialog, `/s/:token`, email gate, visitor comments with forwarding, footer.
8. Setup and settings pages, sign-in cover animation, compose with optional Caddy, README for
   self-hosting, plugin and skill, host hook, deploy, screenshot pass.
